脚本使用说明书（ 普通检测 + 压力老化测试）

适用脚本：DWtest.sh（普通检测）、DWlhtest.sh（压力老化测试）
执行顺序：先做普通检测（DWtest.sh），全部通过后，再做压力老化测试（DWlhtest.sh）
适用环境：x86 服务器（GPU、数据盘、BMC 可选，缺失项自动跳过）
运行要求：root 权限（sudo），建议 CentOS、Ubuntu、RHEL 等常见 Linux 系统

============================================================
一、两个脚本各做什么
============================================================

1. DWtest.sh 普通检测（整机体检）
   - CPU、GPU、风扇、电源、硬盘 SMART、网卡打流、PCIe、CMOS 电池预检
   - dmesg 内核日志与 BMC SEL 日志巡检
   - 硬盘指示灯点灯测试（人工确认）
   - USB 速率检测（人工插拔判定）
   - 耗时参考：约 10 到 30 分钟（打流时长可调）

2. DWlhtest.sh 压力老化测试（burn-in）
   - 硬件预检 + FIO 磁盘压测 + stress-ng CPU + memtester 内存 + gpu-burn 烤机 + NCCL 多卡带宽
   - 后台温度/功耗监控 + 日志巡检
   - 耗时参考：默认 1 小时起步，可调

分工关系：DWtest.sh 负责检查机器各类硬件是否正常；DWlhtest.sh 负责在满负荷下长时间烤机验证稳定性。两个脚本各自独立，日志互不覆盖。

============================================================
二、整体执行流程（照着做即可）
============================================================

1. 测试前准备（见第三部分）
2. 运行普通检测：sudo bash DWtest.sh
3. 查看普通检测日志，确认结果为 ALL TEST PASS（见第六部分）
4. 运行压力老化测试：sudo bash DWlhtest.sh
5. 查看老化测试日志，确认结果为 ALL TEST PASS
6. 保存两份日志目录（<SN>test1.log/ 和 <SN>_test.log/）作为验收留档

注意：普通检测有 FAIL 时，先处理问题，不要直接进入老化测试。

============================================================
三、测试前准备（必做）
============================================================

1. 如用到数据盘，备份数据盘数据
   DWlhtest.sh 的 FIO 会对数据盘整盘写入，数据会被清空。测试前把数据盘数据全部备份，并确认盘位与标签一致。

2. 核对磁盘
   运行 lsblk 人工核对一次：系统盘（根分区所在盘）会被脚本自动排除，数据盘才是压测对象。确认数据盘上没有需要保留的数据。

3. 校准时间
   两个脚本启动时都会校验时间：系统年份不能低于 MIN_YEAR（默认 2025），且系统与 BMC 时间偏差不能超过 60 秒，否则直接终止。
   校准命令参考：
   date -s "2026-08-11 10:00:00" && hwclock -w

4. 准备工号与 SN
   工号格式：DWZN 加 6 位数字，共 10 位，例如 DWZN123456，不符合会要求重输。
   SN 为服务器序列号，任意非空字符串即可。

5. 可选：网卡打流准备（两种方式）
   (1) 对端对打：准备一台对端机器，用网线直连或接入同一交换机；对端机器需安装 iperf3 并预先启动服务端（端口要与脚本 IPERF_PORT 一致，默认 5202）：
       对端机器执行：iperf3 -s -p 5202
       本机 IPERF_PAIRS 填“本机IP:对端IP”。
   (2) 本机自回环（不需要对端机器）：两个网口用一根网线互连，或都接入同一交换机。
       手动方式：两个口各自配好IP，IPERF_PAIRS 填“本机A口IP:本机B口IP”，脚本自动识别为自回环；
       全自动方式：设 IPERF_AUTO_LOOPBACK=1（IPERF_PAIRS 留空），脚本自动找两个链路正常的物理网口、临时配IP
       完成双向打流后自动还原，也可用 IPERF_AUTO_IFACES 指定两个网口（如“eth0 eth3”）。
   不做打流：IPERF_PAIRS 留空且 IPERF_AUTO_LOOPBACK=0，脚本自动跳过。

6. 可选：USB 检测准备
   脚本运行时会显示当前 USB 拓扑、所有已接设备速率分布、主控制器类型（xhci=USB3，ehci/ohci=USB2）供参考。测试时需人工依次将 USB 设备插入各端口，观察 lsusb 协商速率（5000M=USB3.x，480M=USB2.0，12M=USB1.1），确认后再按提示填入各速率设备数量。该项不判 FAIL。

7. 可选项：NCCL 测试准备（多卡 GPU 机器）
   NCCL 带宽测试需要预先编译好 nccl-tests 并放入与脚本同级目录，否则自动跳过。
   存放位置：
     test/
     ├── DWtest.sh
     ├── DWlhtest.sh
     ├── nccl-tests/          ← 新建此目录（与脚本同级）
     │   └── build/           ← 编译产物放这里
     │       └── all_reduce_perf   ← 可执行文件
     └── testSMS              ←脚本使用说明书
   判断条件：① ./nccl-tests/build/all_reduce_perf 存在且可执行；② GPU 数量 ≥ 2。
   两项满足才执行，否则打印 WARN 并跳过，不影响其他测试。
    编译方法（如尚未编译，有内部仓库优先用内部地址）：
      git clone <nccl-tests仓库地址> && cd nccl-tests && make -j
      编译完成后将 build 目录拷贝至脚本同级：cp -r build /path/to/测试脚本/nccl-tests/

8. 依赖工具
   脚本启动时会自动检测并用系统包管理器（apt、dnf、yum）安装缺失依赖（pciutils、ipmitool、smartmontools、iperf3、ledmon、usbutils 等），需要联网或本地源。
   nvidia-smi（需显卡驱动） 不自动安装：缺失时仅跳过 GPU 相关项，不影响其他测试。

============================================================
四、第一步：普通检测（DWtest.sh）
============================================================

4.1 运行方式（三种）

方式一：交互运行（推荐真机使用）
sudo bash DWtest.sh
按提示依次输入：测试人员工号、服务器 SN。

方式二：自动化 / 无人值守（环境变量传参）
TEST_ID=DWZN123456 SERVER_SN=SN0001 LED_TEST=0 IPERF_PAIRS="10.0.1.1:10.0.1.2 10.0.2.1:10.0.2.2" sudo bash DWtest.sh
说明：LED_TEST=0 表示跳过硬盘点灯人工确认（无人值守必加）。

方式三：管道喂入（自动输入密码、工号、SN）
printf 'sudo密码\nDWZN123456\nSN0001\n' | sudo -S env LED_TEST=0 bash DWtest.sh
第一行是 sudo 密码，第二行工号，第三行 SN。

4.2 输入格式要求
工号：DWZN 加 6 位数字，共 10 位，例如 DWZN123456，不符合会要求重输。
SN：任意非空字符串，例如 SN0001。

4.3 执行过程详解（脚本会自动完成）

启动阶段：
1. 权限校验：必须以 root 运行，否则退出。
2. 依赖预检：缺失工具自动安装；nvidia-smi 缺失仅跳过 GPU 项。
3. 时间校验：系统年份、BMC 时间、两者偏差（超过 60 秒终止）。
4. 创建日志目录 ./<SN>test1.log/（注意：普通检测的目录名没有下划线）。
5. 双清空：清空内核 dmesg 缓冲区和 BMC SEL 日志，让本次测试的报错从零开始记录。

阶段 1：硬件信息预检
1.1 CPU 在位检测：读取 CPU 型号、物理颗数、逻辑核数。未识别到 CPU 判 FAIL。
1.2 GPU 在位检测：PCI 层扫描 NVIDIA 显卡。无显卡仅提示，不判失败。
1.3 风扇检测：通过 ipmitool 读风扇转速。读不到判 WARN（检查 BMC）。
1.3.1 电源在位与功率检测：读取电源状态与功率传感器。状态异常判 FAIL。
1.4 硬盘在位与 SMART 健康：列出磁盘并检查 SMART 状态。未识别到磁盘判 FAIL。
1.5 网卡 iperf3 打流：按 IPERF_PAIRS 逐对双向打流（正向加反向）；配对里两个IP都是本机网卡时自动走本机双口自回环（无需对端机器）；IPERF_PAIRS 留空且 IPERF_AUTO_LOOPBACK=1 时走全自动自回环。打流失败判 FAIL；未配置则跳过。
1.5.1 网卡固件采集/升级：默认仅采集信息（NIC_AUTO_UPGRADE=0），不升级。升级失败仅提示，不判失败。
1.6 CMOS 纽扣电池：在位加电压（低于 BAT_LOW_VOLT=2.7V 报警）。异常判 FAIL。
1.7 PCIe 带宽链路信息：打印各 PCIe 设备速率/带宽。仅采集，异常仅提示。
1.8 BMC 待机功耗读取：读取整机功耗传感器。仅采集。

注意：预检发现 FAIL 会直接终止（输出 PRE-CHECK FAIL 并退出），不会进入后续步骤。

阶段 2：硬盘指示灯点灯测试（人工确认）
- 前提：LED_TEST=1（默认）且当前是交互终端；非交互终端自动跳过。
- 过程：第一步点亮蓝色定位灯（locate），第二步点亮橙色故障灯（failure），第三步熄灭所有灯。
- 每步都要目视确认后按 y 回车，按其他键即判 FAIL。
- 若系统盘无法识别或没有数据盘，自动跳过。

阶段 3：日志巡检（dmesg 加 SEL）

3.1 内核日志（dmesg）：Uncorrected error、Machine check、I/O error、panic、Oops 等致命关键词判 FAIL；timeout、reset、fault、ECC 等软性关键词判 WARN（不判失败）；已知无害日志自动过滤。
3.2 BMC SEL：真实硬件故障关键词判 FAIL；日志清空操作记录等白名单内容不判失败。


USB 接口速率检测（人工判定，放最后）：
脚本先显示 lsusb 总线拓扑、设备速率分布、主控制器类型供参考，人工依次插拔设备观察协商速率，确认后按提示输入各速率（USB3.x/USB2.0/USB1.1）设备数量。该项不判 FAIL，仅记录人工判定结果。

最终汇总：
输出本次测试问题项汇总（FAIL），并给出结论：
- ALL TEST PASS（退出码 0）
- TEST FAIL：存在异常项，请查看日志！（退出码 1）

4.4 DWtest.sh 可配置项（环境变量）
TEST_ID：空，非交互模式下的测试人员工号
SERVER_SN：空，非交互模式下的服务器 SN
LED_TEST：1，0 表示跳过硬盘点灯人工确认
IPERF_PAIRS：空，打流网口对，格式为“本机IP:对端IP 本机IP2:对端IP2”；两个IP都写本机网卡IP即自回环（2口一组，4口两两一组）；空则用全自动自回环或跳过
IPERF_PORT：5202，iperf3 端口（避开 5201）
IPERF_TIME：30，单次打流时长（秒）
IPERF_PARALLEL：8，打流并行流数
IPERF_CONNECT_TIMEOUT：10000，单次连接超时（毫秒）
IPERF_AUTO_LOOPBACK：1，1=全自动自回环（IPERF_PAIRS 留空时生效，自动找两个链路正常的物理网口打流）
IPERF_AUTO_IFACES：空，全自动自回环指定网口，如“eth0 eth3”，空则自动挑选
BAT_LOW_VOLT：2.7，CMOS 电池低压告警阈值（伏）
NIC_AUTO_UPGRADE：0，1 表示执行网卡固件升级（需 MFT 与固件目录）
NIC_FW_LOCAL_DIR：./nic_fw，网卡固件本地目录
NIC_ONLINE_UPDATE：0，1 表示在线拉取固件（预留，需外网）
MIN_YEAR：2025，系统时间年份下限

============================================================
五、第二步：压力老化测试（DWlhtest.sh）
============================================================

5.1 运行方式

交互运行（推荐真机使用）：
sudo bash DWlhtest.sh

自动化 / 无人值守：
TEST_ID=DWZN123456 SERVER_SN=SN0001 TEST_TIME=600 FIO_RUN_TIME=300 MEM_RATIO=75 sudo bash DWlhtest.sh

短时冒烟（先快速验证流程）：
TEST_ID=DWZN123456 SERVER_SN=SN0001 TEST_TIME=120 FIO_RUN_TIME=60 MEM_RATIO=20 sudo bash DWlhtest.sh

5.2 执行过程详解

启动阶段：与普通检测相同（root 校验、依赖安装、时间校验、创建日志目录 ./<SN>_test.log/（注意带下划线）、dmesg 和 SEL 双清空）。

阶段 1：硬件信息预检：同 DWtest.sh 的 1.1 到 1.4、1.5.1（网卡固件采集）、1.6 到 1.8（不含 iperf 打流）。预检 FAIL 直接退出（PRE-CHECK FAIL）。

阶段 2：压力老化测试（核心阶段）
2.1 FIO 顺序读写：每块数据盘 128k 块、队列深度 32、顺序写加顺序读各跑 FIO_RUN_TIME 秒，整盘写入。出现 I/O error 等判 FAIL。
2.2 CPU 压力：stress-ng --cpu 全部逻辑核 --cpu-method all，跑 TEST_TIME 秒。异常退出判 WARN。
2.3 内存压力：memtester 占用 MEM_RATIO% 总内存（默认 75%），跑 1 轮。检测到内存错误判 FAIL。
2.4 GPU 烤机：gpu-burn -d TEST_TIME 双精度烤机（需 gpu-burn 加 CUDA 环境）。异常退出判 WARN。
2.5 NCCL 带宽：多卡 AllReduce 带宽测试（8M 到 1G），需至少 2 张 GPU 且已编译 ./nccl-tests/build/all_reduce_perf。失败仅警告。

补充说明：
- 2.2、2.3、2.4 三个压力项并行运行，全部结束后再跑 2.5。
- 全程有后台实时监控：每 60 秒采集一次 CPU 最高温度、整机功耗、GPU 温度/功耗/利用率、内存使用率、风扇最高转速，写入 monitor.csv。
- CPU 温度超过 CPU_TEMP_ALERT（默认 80 度）会写温度告警标记，测试结束时若存在该标记判 FAIL。
- 有总超时保护（TEST_TIME 加 600 秒缓冲），防止压力项卡死挂起。

阶段 3：日志巡检：dmesg 加 BMC SEL，规则与普通检测相同。

最终汇总：同普通检测，输出问题项汇总与 ALL TEST PASS 或 TEST FAIL。

5.3 DWlhtest.sh 可配置项（环境变量）
TEST_ID：空，非交互模式下的测试人员工号
SERVER_SN：空，非交互模式下的服务器 SN
TEST_TIME：3600，CPU/GPU 压力时长（秒），即老化时长
FIO_RUN_TIME：600，每块数据盘 FIO 顺序写/读各跑时长（秒）
MEM_RATIO：75，memtester 占用内存比例（%）
MEMT_TIMEOUT：0，memtester 超时限制（秒），0 表示不限制
CPU_TEMP_ALERT：80，CPU 温度告警阈值（摄氏度）
BAT_LOW_VOLT：2.7，CMOS 电池低压告警阈值（伏）
NIC_AUTO_UPGRADE：0，1 表示执行网卡固件升级（预留）
NIC_FW_LOCAL_DIR：./nic_fw，网卡固件本地目录
NIC_ONLINE_UPDATE：0，1 表示在线拉取固件（预留）
MIN_YEAR：2025，系统时间年份下限

============================================================
六、日志查看方式
============================================================

6.1 日志目录（两个脚本目录名不同，注意区分）
DWtest.sh 普通检测：./<SN>test1.log/（无下划线），生成在运行脚本时所在的目录
DWlhtest.sh 老化测试：./<SN>_test.log/（有下划线），生成在运行脚本时所在的目录
例如 SN 为 SN0001 时，分别是 ./SN0001test1.log/ 和 ./SN0001_test.log/。

6.2 日志文件清单
main.log：主日志，各阶段输出、检测结果、FIO 带宽/IOPS、压力项结果、问题汇总。第一优先查看。
dmesg.log：内核关键报错（带 FAIL/WARN 分级和原因注释）。用于查硬件故障。
sel.log：BMC SEL 关键告警（带原因注释）。用于查 BMC 硬件告警。
monitor.csv：老化测试温度/功耗采样（仅 DWlhtest.sh 生成）。用于看温度曲线。

6.3 常用查看命令
实时查看主日志（推荐在另一个终端执行，测试进行中也能看）：
tail -f ./SN0001test1.log/main.log          （普通检测）
tail -f ./SN0001_test.log/main.log          （老化测试）

查看完整主日志：
less ./SN0001test1.log/main.log
less ./SN0001_test.log/main.log

快速看最终结论：
grep "【最终结果】" ./SN0001test1.log/main.log
grep "【最终结果】" ./SN0001_test.log/main.log

查看问题项汇总：
grep -E "问题项汇总|FAIL" ./SN0001test1.log/main.log
grep -E "问题项汇总|FAIL" ./SN0001_test.log/main.log

查看专项日志：
cat ./SN0001test1.log/dmesg.log
cat ./SN0001test1.log/sel.log
cat ./SN0001_test.log/dmesg.log
cat ./SN0001_test.log/sel.log

6.4 老化测试温度曲线（monitor.csv）
直接cat或用表格软件查看 monitor.csv，对“CPU最高温度(℃)”和“GPU最高温度(℃)”列画折线图即可看到全程温度走势。
温度参考红线：CPU 持续高于 80 度、GPU 高于 85 度、NVMe 高于 70 度应停机排查散热。
CSV 列顺序：采集时间、CPU最高温度、整机功耗、GPU最高温度、GPU总功耗、GPU最大利用率、内存使用率、风扇最高转速。

6.5 如何判定结果
两个脚本的 main.log 末尾都会打印以下结论之一：
- ALL TEST PASS：通过（退出码 0）
- TEST FAIL：存在异常项，请查看日志！（退出码 1）
- PRE-CHECK FAIL：预检阶段就失败，直接退出（退出码 1）
查看“问题项汇总”区域的每一行 FAIL，逐条确认原因。
注意：DWtest.sh 的点灯、USB 是人工/插拔项目，ALL TEST PASS 的前提是人工确认无误；老化测试请同时看 monitor.csv 温度曲线是否异常。

============================================================
七、常见问题与注意事项
============================================================

1. FIO 会清空数据盘：DWlhtest.sh 整盘写入，务必先备份；系统盘已自动排除。
2. 点灯测试需要人在现场：无人值守请加 LED_TEST=0，否则非交互终端会自动跳过（日志留 WARN）。
3. iperf 打流两种方式：对端对打需对端机器先跑 iperf3 -s -p 5202，IPERF_PAIRS 填“本机IP:对端IP”；本机自回环不需要对端机器，两个网口用网线互连或接同一交换机，IPERF_PAIRS 填“本机A口IP:本机B口IP”（脚本自动识别），或设 IPERF_AUTO_LOOPBACK=1 全自动；测试期间被测网口会短暂断网，别用它们做 SSH 管理。
4. 大内存机型：memtester 默认吃 75% 内存且不设超时，512GB 以上机器可能跑数小时，按需调低 MEM_RATIO 或设置 MEMT_TIMEOUT。
5. 虚拟化/无 BMC 环境：GPU、BMC、数据盘等缺失项会自动跳过，仍可 PASS，仅用于流程验证。
6. 时间不对会直接终止：先 date 校准，再和 BMC 时间比对，偏差要在 1 分钟内。
7. 中途 Ctrl+C：脚本已注册清理函数，会终止后台压力进程/监控、熄灭硬盘灯、清理临时文件。
8. NCCL测试：同第七部分第7条，满足条件才执行，否则WARN跳过。
9. 普通检测没通过不要进入老化：先处理 FAIL 项，避免在故障机器上浪费时间与风险。
